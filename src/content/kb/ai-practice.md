# How I work with AI

I am a heavy, deliberate user of agentic coding tools, not as an autocomplete toy but as a disciplined part of how I deliver software. Across Claude Code and Codex I have run more than 1,100 coding sessions and about 3.3 billion tokens, working with 16 different models, from Claude Opus 4.8, Sonnet 5 and Haiku 4.5 to the GPT-5 Codex line. I have been building with these agents since 2025.

Claude Code is my main tool for feature work, refactors and debugging, and I run it as an orchestrator. The main session plans the work, writes a dispatch brief with checkable "Done when" criteria, and hands it to a subagent: a Sonnet implementer for short tasks, an Opus implementer for long or complex ones, and a read-only Sonnet researcher for wide searches. Opus and Fable reviewers give a second review that is not anchored on the orchestrator's view. Subagents never build, test or lint. Only the orchestrator reads the diff, runs the checks and accepts the work, and a claim without evidence counts as not done. Codex I run alongside as an independent second agent under the same rules, written in its own AGENTS.md, to cross-check changes and explore alternative approaches. Cursor I use for fast inline edits when the change is small and I want to stay in the file.

The way I use AI is governed by my personal CLAUDE.md. The core rules: deterministic decisions such as routing, retry policy, thresholds and escalation rules live in explicit code, and the model only classifies, summarizes, drafts and resolves ambiguity, never deciding facts that have a right answer. Errors are always thrown, returned or reported, never swallowed behind default values, and batch jobs that skip records report the count and reasons. Every iteration loop has a defined budget in iterations, tokens or time. Before writing code I climb a reuse ladder: does it need to exist, is there a helper in the codebase, the standard library, a platform feature, an installed dependency, then a proven open-source project. Bug fixes start from a reproduction close to real use, and the failing test is committed before the fix. Each major feature keeps a committed HANDOVER doc so any agent in any worktree can pick up the work.

The rules that matter most are enforced by Claude Code hooks, not by the model remembering them. Hooks block pushes to protected branches and AI attribution in commit messages, stop subagents from running checks, and give every subagent the same working rules when it starts. My CLAUDE.md, Codex AGENTS.md, subagent definitions, hooks and skills live in one private, versioned config repo that two machines link to. A cleaned public export of it, claude-config-starter on GitHub, gives students the same starting point with an installer.

This portfolio's chat is itself an example of that discipline: a grounded RAG service where high-risk facts come from retrieval, not from the model, with an answerability gate that refuses to answer when evidence is missing.
